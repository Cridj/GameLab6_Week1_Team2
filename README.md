# HOPAK SNAKE · 호팍 스네이크

**호팍춤을 추며 시민을 모으고, 길어진 대열로 다른 플레이어를 압박하는 멀티플레이 게임입니다.**

A / D를 번갈아 누르는 리듬과 지렁이 게임의 성장·경쟁을 결합했습니다. 시민을 모아 몸집을 키우고, 콤보로 충전한 대시를 추격과 회피에 사용합니다.

## 플레이 흐름

1. 캐릭터의 외형과 닉네임을 정합니다.
2. 초록색 시민에게 닿아 대열에 합류시키고 크기와 이동 속도를 키웁니다.
3. A / D 콤보를 유지하며 대시 게이지를 채웁니다.
4. 대시로 다른 플레이어를 추격하거나 위험한 상황에서 빠져나옵니다.
5. 상대의 머리를 내 대열에 부딪히게 만들고, 상대가 남긴 시민을 모아 다시 성장합니다.

| 조작 | 동작 |
| --- | --- |
| A / D 번갈아 입력 | 리듬에 맞춰 콤보 유지 |
| 마우스 좌우 이동 | 방향 전환 |
| 마우스 왼쪽 버튼 유지 | 게이지를 소모해 대시 |
| 사망 후 Space | 메인 로비로 돌아가기 |

## 피드백을 반영한 변화

### 콤보를 쌓는 이유 만들기

기존 게임에서는 콤보가 쌓일수록 빨라졌지만, 그만큼 피하기 어려워진다는 피드백이 있었습니다. 개인과제에서는 콤보가 높을수록 대시 게이지를 더 빨리 충전하도록 바꿨습니다. 리듬을 유지한 보상을 추격과 회피에 사용할 수 있도록 연결했습니다.

현재 코드에는 콤보가 끊겼을 때 기본 속도까지 감속하는 처리도 들어 있습니다.

### 내 캐릭터를 알아보기 쉽게

첫 플레이 테스트에서 다른 플레이어와 구분하기 어렵다는 의견을 받았습니다. 몸 색상과 모자·얼굴 장식을 고르는 커스터마이징을 추가했고, 코드에서는 본인과 다른 플레이어의 신발 색도 구분합니다.

### 커지는 재미와 시야의 균형

크기가 커지고 대열이 길어지는 모습 자체를 보상으로 삼았습니다. 반면 몸집이 커졌을 때 작은 상대가 가려지는 문제도 피드백으로 남았습니다. 성장의 시각적 재미를 살리면서 주변 상황을 읽기 쉽게 만드는 것이 다음 개선 과제입니다.

## 멀티플레이 구현

### 팔로워가 같은 경로를 따라가도록

[NetworkPlayer.cs](Assets/Scripts/Player/NetworkPlayer.cs)에서 서버가 플레이어의 이동 경로를 기록하고 경로점을 묶어 전달합니다. [FollowerManager.cs](Assets/Scripts/Player/FollowerManager.cs)는 그 경로를 따라 일정 거리 뒤의 위치를 구해 대열을 배치합니다.

경로점에는 순번을 붙입니다. 클라이언트가 순번 누락을 감지하면 스냅샷을 요청하고, 새로 접속한 플레이어도 현재 경로와 팔로워 수를 전달받도록 구성했습니다. 화면에 생성하는 팔로워 수와 누적 획득 수는 구분해 관리합니다.

### 사망과 접속 종료 처리

[GameManager.cs](Assets/Scripts/Managers/GameManager.cs)는 시민의 생성 정보, 플레이어 목록과 순위를 관리합니다. 사망 시에는 남아 있는 대열 경로를 기준으로 시민을 배치해 묶음으로 전달합니다.

현재 코드에는 연결 종료 시 플레이어 목록과 순위를 정리하는 처리, 사망 상태 동기화, 입력 이벤트 해제도 포함되어 있습니다. 이는 구현 상태를 설명한 것으로, 모든 네트워크 상황에서 동작을 검증했다는 의미는 아닙니다.

## 실행 환경

- **Unity 6000.0.55f1**
- C#, FishNet, Unity Input System, DOTween
- 씬 흐름: `MainLobby → Customize → MultiScene`

저장소를 클론한 뒤 Unity Hub에서 루트 폴더를 추가합니다. Unity 버전은 [ProjectVersion.txt](ProjectSettings/ProjectVersion.txt), 빌드 씬 목록은 [EditorBuildSettings.asset](ProjectSettings/EditorBuildSettings.asset)에서 확인할 수 있습니다.

멀티플레이에는 별도의 서버 실행이 필요합니다. [GameScene.cs](Assets/Scripts/Managers/GameScene.cs)는 `isServer` 값에 따라 서버 또는 클라이언트 연결을 시작합니다. 서버용 실행에서는 이를 켜고, 클라이언트에서는 끈 상태로 사용하며 FishNet Transport의 접속 주소와 포트를 실행 환경에 맞춰 설정해야 합니다.

## 테스트와 회고

개인과제 당시 A반 동료들과 네 차례 플레이 테스트를 진행하며 조작, 피아 식별, 성장 속도와 멀티플레이에 대한 의견을 받았습니다. 여러 사람이 동시에 접속할 때 생기는 문제를 직접 경험했고, 최적화와 동기화에 시간을 쓰면서 콘텐츠 추가와 안정성 사이의 우선순위도 고민했습니다.

당시 회고에는 강제 종료 후 플레이어가 남는 문제와 동기화 품질에 대한 아쉬움이 기록되어 있습니다. 이후 코드에는 종료 처리와 경로 스냅샷 복구가 들어 있지만, 개선 효과는 실제 다중 클라이언트 환경에서 다시 확인할 필요가 있습니다.

- **10명 이상 동시 접속은 당시 테스트하지 않았습니다.**
- 큰 캐릭터가 작은 상대를 가리는 시야 문제, A / D 입력 안내는 추가 개선 항목입니다.
- 현재 버전의 빌드 성공과 네트워크 스트레스 테스트 결과는 이 README에서 보장하지 않습니다.
